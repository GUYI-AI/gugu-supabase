# Conversations owned entirely by an erased identity set

Account erasure now removes a conversation when none of its members is outside the human and all of that human's owned agents, including removed agents. The decision does not depend on dm, ai, group or topic kind. Messages, file items/versions, memberships and source topics cascade in the same database transaction. A conversation with another human or another owner's agent remains; its deleted authors still use the existing null-author display behavior.

The helper starts closed to every API role and requires the current transaction's exact private erasure context. It considers memberships and creator attribution, locks sources before topics and all affected membership rows before rechecking, then runs before the original shared-chat/command/identity/storage cleanup. A join that commits first must be observed and preserve the conversation. A join that reaches the foreign-key fence after deletion cannot recreate its seat. An inconsistent legacy topic with an outside participant prevents source deletion rather than losing that participant's content.

Deleting a chat makes the existing file-delete guard recognize a cascade; no caller-set flag bypasses the ordinary system-folder or nonempty-folder rules. The helper captures legacy object pointers before cascading, including source topics, avatars, outputs and transfer-storage references. Lost modern references already enter the blob collector. Legacy pointers with no surviving reference are registered with that same collector. Shared copies and live upload/download capabilities remain governed by its existing reference/lease checks. Queue registration is atomic with account deletion; physical storage deletion happens through the established asynchronous collector, not an external I/O operation inside the database transaction.

## Release shape

Forward migration `20261119132000` requires the two-argument `identity.erase_human_account(text,text)` installed by `20261119001400`, including its private audit-registration call and the indexed command predicates from `071502`. It inserts exactly one closed helper call after the installed personal-list snapshot and before its prelock prelude and original chat loop and rejects an unknown predecessor. The one-argument compatibility wrapper and trusted Auth trigger are unchanged.

Order is `071502` → audit helpers `20261119001000/20261119001100` → registered audit `20261119001200/20261119001300` → unified `20261119001400` → personal-list lock order `20261119013001` (through `20261119013005`) → this `20261119132000` → paired principal releases `20261119132100/20261119132200`. `20261119001100` defines audit helpers rather than replacing the erasure body. `20261119001400` clones the indexed one-argument body and installs the wrapper, so this release must patch the two-argument body afterwards. `20261119132100` guards Auth aliases; private `20261119132200` patches `billing.erase_accounting_identity`, a separate trigger function. Neither is a replacement for this body's predecessor check. Existing installed migration bytes and release ledgers are not modified.

## Distinct remove-agent behavior

`identity.remove_owned_agent` is unchanged. Its existing path archives the agent's dm/ai and agent-created groups and deletes messages in those archived conversations; it does not delete the conversation rows. It retains the owner and a lifecycle tombstone rather than erasing the complete human identity set. Previously account erasure preserved all conversation/message rows, which was weaker even for self-only content. This release fixes that account-erasure case, but the two operations still have different predicates and retention behavior. It does not claim they have been made identical. Changing the remove-agent operation requires its separate product decision and migration.

## Validation and limits

The disposable tests cover the seven required membership/kind cases, source-topic/file cascades, shared and exclusive objects, closed capability/context refusal, both real two-connection join races and actual Auth HTTP deletion before/after with identical synthetic message counts. The benchmark restores the exact installed body without the new call only inside the owned serial test phase; all other suites run after restoration. Results and final source head are recorded in the draft review after CI completes. A small loopback fixture cannot establish the original deployment's total deletion budget; the full-scale Auth path still requires its independent measurement before rollout.
