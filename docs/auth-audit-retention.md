# Auth audit retention

Release `20261115100000` adds closed helpers; it does not change the unified Auth deletion entry. Install the separately reviewed platform-owner time index first, then these helpers, then the unified caller. No platform owner or role membership changes are needed when the existing narrow DML privileges are present.

`identity.erase_auth_audit_actor(text[],text)` requires the exact current transaction's full ordered privacy-erasure identity set. The second argument is the Auth deletion row's email, passed only in function parameters. NULL/empty email still performs all ID matching. The caller owns context creation and removal. Helper errors must roll back the deletion transaction.

The whitelist is based on [Auth v2.196.0 actor fields](https://github.com/supabase/auth/blob/v2.196.0/internal/models/audit_log_entry.go), [administrator target traits](https://github.com/supabase/auth/blob/v2.196.0/internal/api/admin.go), and [email-provider identity traits](https://github.com/supabase/auth/blob/v2.196.0/internal/api/identity.go). Matching actor ID or full normalized email removes actor_username/actor_name; matching target user_id/user_email removes traits.user_email/user_phone. Email-provider provider_id is removed only for a matching actor or full email. A target-only match leaves a different administrator's fields intact. No substring/prefix matching, arbitrary recursive JSON cleanup or persistent identity mapping is used. IDs, actions, timestamps, IPs and unrelated fields remain during retention. Unknown paths are not claimed to be covered. External Auth process/request logs are outside this database helper.

The independent cron runs every ten minutes, initially at most 100 rows, with a hard function limit of 1000. It deletes only `created_at < now() - interval '180 days'`, preserves NULL dates, orders by `(created_at,id)`, and skips locked rows. Each invocation requires an already active positive statement timeout of at most two seconds and uses a 100ms lock timeout. A zero result is a single batch observation, not proof that locked records or future expirations are absent.

The fixed index is `auth.audit_log_entries_created_at_id_idx`, a nonunique, nonpartial btree on exactly `(created_at,id)`. Create it with `CONCURRENTLY IF NOT EXISTS` outside transactions and under a short lock timeout. Read back definition, indisvalid and indisready; an existing mismatched or invalid index is a stop, never an automatic DROP/rebuild. Platform-owner preparation is a separate reviewed CD operation; it is not an application OWNER/GRANT repair payload. The migration refuses missing privileges, filtered RLS visibility or a missing/mismatched index.

Before the first production cleanup, the release manager obtains a bounded read-only expired-count/earliest-day and index/owner catalog receipt. Do not infer production backlog from fixture data. Measure concurrent Auth writes while preparing the staging index, and measure indexed pruning/redaction on synthetic scale. True Auth deletion, compatibility entry, atomic rollback and both audit helpers are verified with the unified caller before release.
